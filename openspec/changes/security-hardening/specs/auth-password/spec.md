# auth-password Specification（增量）

## 新增需求

### 需求：密码必须以 BCrypt 哈希存储

系统存储的用户与管理员密码必须是 BCrypt 哈希（`$2a$` 前缀），任何写入口（注册、管理员新增、重置密码）不得落明文。

#### 场景：新用户注册

- **当** 新用户提交注册表单
- **则** 库中该账号 password 字段为 BCrypt 哈希，长度 60 字符

#### 场景：管理员重置用户密码

- **当** 管理员对某用户执行重置密码
- **则** 新密码以哈希入库；接口返回值中的临时明文密码仅本次响应可见，不落日志

### 需求：存量明文密码首次登录自动升级

已有明文密码的账号在首次成功登录后，系统必须自动将其密码改写为 BCrypt 哈希，用户无感知。

#### 场景：明文账号首次登录

- **当** 账号库中密码为明文，用户以正确明文密码登录
- **则** 登录成功，且登录事务内将该字段回写为 BCrypt 哈希

#### 场景：升级后再次登录

- **当** 已升级为哈希的账号再次登录
- **则** 走 BCrypt matches 校验，正常登录，不再触发回写

#### 场景：明文账号密码错误

- **当** 库中为明文但提交密码错误
- **则** 登录失败，库中数据不变
