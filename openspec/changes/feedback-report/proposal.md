# Proposal: feedback-report（读者违规举报与管理员处理通道）

## 为什么

论文摘要承诺"线上举报反馈机制使得不文明行为有效降低"，但代码从未实现——读者对喧哗/饮食/占座等行为没有向管理员反馈的通道（仅有聊天室匿名发言这一非正式途径），管理员仍依赖巡查。补齐这一核心业务闭环。

## 改什么

- 新表 `feedback`（举报人/楼层/被举报人与关联消息/类型 TALK·EAT·SEAT_OCCUPY·OTHER/描述/匿名/状态 0待处理·1已处理·2驳回/处理备注）
- 用户端：聊天室内对任意消息"举报"（弹窗选类型+描述，可匿名）；60 秒内仅可提交一次（Redis SETNX 防滥用）
- 管理端：举报列表（分页/按状态筛选，联表显示双方昵称）+ 处理/驳回；新举报实时 WS 推送给在线管理员
- 匿名语义：对管理员展示"匿名"，但库中保留 reporter_id 可溯源（与聊天室匿名一致的设计权衡）

## 非目标

- 占座举报的"限时确认否则释放"机制（独立变更 report-release，proposal 已在档）
- 举报积分/信用体系、图片取证

## 验收

1. 聊天室对消息举报成功落库；60 秒内二次举报被拒
2. 在线管理员实时收到新举报通知
3. 管理端列表可见（匿名者显示"匿名"）、可标记已处理/驳回并留备注
4. 用户端"我的举报"可见处理状态
