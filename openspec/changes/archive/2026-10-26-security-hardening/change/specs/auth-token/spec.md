# auth-token Specification（增量）

## 新增需求

### 需求：JWT 使用独立服务端密钥签发与验签

token 的签名密钥必须是服务端独立配置的 `JWT_SECRET`（环境变量注入），不得使用任何用户数据派生；payload 携带 `userId` 与 `role`（user/admin）。

#### 场景：登录签发

- **当** 用户或管理员登录成功
- **则** 返回的 token 以 HMAC256(JWT_SECRET) 签名，payload 含 userId、role，有效期 4 小时

#### 场景：验签不查库

- **当** 携带合法 token 访问受保护 REST 接口
- **则** 拦截器仅凭密钥本地验签，不产生数据库查询，并将 userId/role 注入请求上下文

#### 场景：token 篡改

- **当** token 任意字符被篡改后请求
- **则** 验签失败，返回 401，不进入业务逻辑

#### 场景：生产环境缺密钥拒绝启动

- **当** 应用以非开发配置启动且 JWT_SECRET 未配置或为默认值
- **则** 启动失败并给出明确错误（fail-fast）

### 需求：已删除用户的有效 token 不得继续使用

#### 场景：持旧 token 访问需身份的接口

- **当** token 验签通过但 payload 对应用户已被删除，且接口需要用户信息
- **则** 返回明确错误（用户不存在），不返回任何用户数据
